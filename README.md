# ofsla-test

Тренажёр для подготовки к экзамену на свидетельство пилота параплана ОФСЛА (тест «Пилот СВС 115», пилоты-парапланеристы 3–5 уровней).

Наведите камеру телефона на QR-код.

## Источник

`doc/pilot_svs_115_bez_otvetov.pdf` — экзаменационный тест из системы тестирования INDIGO (29.06.2023):
432 вопроса в 6 разделах. Ключ ответов — в конце документа, на страницах «Ключи».

| Раздел | Вопросов |
|---|---|
| Воздушное законодательство | 26 |
| Аэродинамика | 92 |
| Практика полета | 155 |
| Конструкция, эксплуатация параплана и оборудования | 69 |

| Возможности человека и оказание первой медицинской помощи | 27 |

## Структура

```
doc/                          исходный PDF, QR-коды со ссылками на сайт и бота
tools/extract_questions.py    извлечение вопросов, картинок и ключа из PDF
data/questions.json           банк вопросов (генерируется)
data/img/q{N}.png             картинки к вопросам (генерируются)
web/                          веб-приложение (Vite + TypeScript + Preact, PWA)
```

## Перегенерация данных

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python tools/extract_questions.py
```

Скрипт проверяет результат: все номера 1..432 на месте, у каждого вопроса есть текст и не меньше двух вариантов, ключ ссылается на существующие варианты. При ошибке он печатает `ERROR: …` и завершается с кодом 1.

## Веб-приложение

Нужен Node.js 20+.

```sh
cd web
npm install
npm run dev        # разработка: http://localhost:5173
npm test           # тесты логики (Vitest)
npm run build      # проверка типов и сборка в web/dist
npm run preview    # запуск собранной версии: http://localhost:4173
```

Режимы:

- **Обучение по разделам** — раздел или все вопросы, по порядку или вперемешку, можно оставить только неосвоенные. После ответа сразу показывается правильный.
- **Пробный экзамен** — случайный билет, вопросы из разделов пропорционально их размеру. Есть таймер, переход между вопросами, пропуск и возврат. По умолчанию 40 вопросов, 45 минут, порог 90%; параметры меняются в настройках. Как в оригинале, у вопросов с одним ответом радиокнопки, с несколькими — чекбоксы. Если закрыть страницу посреди экзамена, попытка продолжится с того же места.
- **Статистика** — освоенные вопросы по разделам (освоен = два последних ответа верны), история экзаменов с разбором ошибок.

Прогресс хранится в браузере (`localStorage`) и на другие устройства не переносится (кроме запуска из Telegram, см. ниже). Приложение устанавливается на телефон как PWA и после первого открытия работает без интернета: service worker кэширует вопросы и картинки. Установка PWA требует HTTPS или `localhost`.

Данные не копируются в `web/`: Vite раздаёт `data/` как `publicDir`. После перегенерации `questions.json` достаточно пересобрать приложение.

### Telegram Mini App

Тот же сайт открывается внутри Telegram. Сервер для бота не нужен: Telegram просто открывает ссылку на GitHub Pages.

Внутри Telegram приложение:
- синхронизирует прогресс, историю и незавершённый экзамен через Telegram CloudStorage — они общие для всех устройств, где открыт бот. При запуске данные устройства объединяются с облачными; если облако не ответило, приложение работает с локальными данными;
- берёт цвета из темы Telegram и использует его кнопку «Назад»;
- даёт вибрацию при ответе и спрашивает подтверждение, если закрыть приложение во время экзамена.

SDK (`@twa-dev/sdk`) загружается только при запуске из Telegram; в обычном браузере приложение не меняется.

Подключение бота (один раз, в Telegram):
1. @BotFather → `/newbot` → имя и username бота.
2. @BotFather → `/mybots` → бот → Bot Settings → Configure Mini App → Enable Mini App → URL `https://rubbercthulhu.github.io/ofsla-test/`.
3. Там же Bot Settings → Menu Button → URL тот же, текст кнопки, например «Тренажёр».

Бот проекта — [@OFSLAtestBot](https://t.me/OFSLAtestBot). Приложение открывается кнопкой меню в чате с ботом или прямой ссылкой https://t.me/OFSLAtestBot/trainer (зарегистрирована через `/newapp`, short name `trainer`; обложка — `doc/miniapp-cover.png`).

### Публикация

Сайт публикуется на GitHub Pages автоматически при push в `main` (`.github/workflows/deploy.yml`): установка зависимостей, тесты, сборка, деплой `web/dist`. Если тесты не прошли, сайт не обновляется. Статус — на вкладке Actions репозитория.

## Формат `data/questions.json`

```json
{
  "source": "pilot_svs_115_bez_otvetov.pdf",
  "title": "Пилот СВС 115",
  "sections": ["Воздушное законодательство", "..."],
  "questions": [ ... ]
}
```

Поля вопроса:

| Поле | Описание |
|---|---|
| `id` | номер вопроса в PDF (1..432) |
| `section` | название раздела, одно из `sections` |
| `type` | `single` — один правильный ответ, `multiple` — несколько, `matching` — сопоставление |
| `text` | текст вопроса |
| `image` | путь к картинке относительно `data/` (`"img/q92.png"`) или `null` |
| `options` | варианты ответа `[{"id": 1, "text": "..."}]`; для `matching` — правая колонка |
| `items` | только `matching`: левая колонка (что сопоставляем) |
| `columns` | только `matching`: заголовки колонок таблицы или `null`, если в PDF их нет |
| `correct` | `single`/`multiple`: список `id` правильных вариантов; `matching`: объект `{"id пункта": id варианта}` |

Одиночный выбор:

```json
{
  "id": 12,
  "section": "Воздушное законодательство",
  "type": "single",
  "text": "Какой признак, применяемый для поля 18 (Прочая информация) сообщения о плане полета, соответствует типу воздушного судна?",
  "image": null,
  "options": [{"id": 1, "text": "OPR/"}, {"id": 2, "text": "TYP/"}, {"id": 3, "text": "RMK/"}],
  "correct": [2]
}
```

Множественный выбор — то же самое, но `"type": "multiple"` и несколько id в `correct`, например `[1, 2, 3, 5]`.
В PDF такие вопросы оформлены так же, как одиночные (в самом экзамене у них чекбоксы), поэтому тип определяется только по ключу.

Сопоставление:

```json
{
  "id": 309,
  "type": "matching",
  "text": "Как называются точки 3, 4 и 5 на рисунке?",
  "image": "img/q309.png",
  "columns": ["Номера на рисунке", "Название узла"],
  "items": [{"id": 1, "text": "3"}, {"id": 2, "text": "4"}, {"id": 3, "text": "5"}],
  "options": [{"id": 1, "text": "Конец крыла"}, {"id": 2, "text": "«Ухо» (консоль) крыла"}, "..."],
  "correct": {"1": 2, "2": 3, "3": 6}
}
```

## Известные особенности данных

- Текст вопросов и вариантов сохранён как в источнике, вместе с опечатками (например, «линскорений» в №432, «5 эелемент» в №320).
- Исправлены только символы, которые в текстовом слое PDF набраны не тем алфавитом: `RМК/` → `RMK/`, `Сx` → `Cx`, однобуквенные варианты «А/В/С» → латиница.
- У №372 в источнике вместо текста вопроса стоит фраза, похожая на вариант ответа («прохождение любого фронта происходит сначала на высоте»).
- В №321 текст вопроса говорит о точках «1, 2 и 4», но в самом тесте пунктов пять (1, 2, 4, 5, 6), и ключ тоже на пять.
