# ofsla-test

Тренажёр для подготовки к экзамену на свидетельство пилота параплана ОФСЛА (тест «Пилот СВС 115», пилоты-парапланеристы 3–5 уровней).

**Статус:** банк вопросов извлечён в JSON. Формат самого приложения (веб или Telegram-бот) ещё не выбран.

## Источник

`doc/pilot_svs_115_bez_otvetov.pdf` — экзаменационный тест из системы тестирования INDIGO (29.06.2023):
432 вопроса в 6 разделах. Ключ ответов — в конце документа, на страницах «Ключи».

| Раздел | Вопросов |
|---|---|
| Воздушное законодательство | 26 |
| Аэродинамика | 92 |
| Практика полета | 155 |
| Конструкция, эксплуатация параплана и оборудования | 69 |
| Авиационная метеорология | 63 |
| Возможности человека и оказание первой медицинской помощи | 27 |

## Структура

```
doc/                          исходный PDF
tools/extract_questions.py    извлечение вопросов, картинок и ключа из PDF
data/questions.json           банк вопросов (генерируется)
data/img/q{N}.png             картинки к вопросам (генерируются)
```

## Перегенерация данных

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python tools/extract_questions.py
```

Скрипт проверяет результат: все номера 1..432 на месте, у каждого вопроса есть текст и не меньше двух вариантов, ключ ссылается на существующие варианты. При ошибке он печатает `ERROR: …` и завершается с кодом 1.

## Формат `data/questions.json`

```json
{
  "source": "pilot_svs_115_bez_otvetov.pdf",
  "title": "Пилот СВС 115",
  "sections": ["Воздушное законодательство", "..."],
  "questions": [ ... ]
}
```

Поля вопроса:

| Поле | Описание |
|---|---|
| `id` | номер вопроса в PDF (1..432) |
| `section` | название раздела, одно из `sections` |
| `type` | `single` — один правильный ответ, `multiple` — несколько, `matching` — сопоставление |
| `text` | текст вопроса |
| `image` | путь к картинке относительно `data/` (`"img/q92.png"`) или `null` |
| `options` | варианты ответа `[{"id": 1, "text": "..."}]`; для `matching` — правая колонка |
| `items` | только `matching`: левая колонка (что сопоставляем) |
| `columns` | только `matching`: заголовки колонок таблицы или `null`, если в PDF их нет |
| `correct` | `single`/`multiple`: список `id` правильных вариантов; `matching`: объект `{"id пункта": id варианта}` |

Одиночный выбор:

```json
{
  "id": 12,
  "section": "Воздушное законодательство",
  "type": "single",
  "text": "Какой признак, применяемый для поля 18 (Прочая информация) сообщения о плане полета, соответствует типу воздушного судна?",
  "image": null,
  "options": [{"id": 1, "text": "OPR/"}, {"id": 2, "text": "TYP/"}, {"id": 3, "text": "RMK/"}],
  "correct": [2]
}
```

Множественный выбор — то же самое, но `"type": "multiple"` и несколько id в `correct`, например `[1, 2, 3, 5]`.
В PDF такие вопросы оформлены так же, как одиночные, поэтому тип определяется только по ключу.

Сопоставление:

```json
{
  "id": 309,
  "type": "matching",
  "text": "Как называются точки 3, 4 и 5 на рисунке?",
  "image": "img/q309.png",
  "columns": ["Номера на рисунке", "Название узла"],
  "items": [{"id": 1, "text": "3"}, {"id": 2, "text": "4"}, {"id": 3, "text": "5"}],
  "options": [{"id": 1, "text": "Конец крыла"}, {"id": 2, "text": "«Ухо» (консоль) крыла"}, "..."],
  "correct": {"1": 2, "2": 3, "3": 6}
}
```

## Известные особенности данных

- Текст вопросов и вариантов сохранён как в источнике, вместе с опечатками (например, «линскорений» в №432, «5 эелемент» в №320).
- Исправлены только символы, которые в текстовом слое PDF набраны не тем алфавитом: `RМК/` → `RMK/`, `Сx` → `Cx`, однобуквенные варианты «А/В/С» → латиница.
- У №372 в источнике вместо текста вопроса стоит фраза, похожая на вариант ответа («прохождение любого фронта происходит сначала на высоте»).
- В №321 текст вопроса говорит о точках «1, 2 и 4», но в самом тесте пунктов пять (1, 2, 4, 5, 6), и ключ тоже на пять.
